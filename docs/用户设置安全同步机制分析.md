# Epic-Stack 用户设置安全同步机制分析报告

## 1. 整体架构概览

### 1.1 页面路由结构

Epic-Stack 的用户设置页面采用 **Remix 嵌套路由** 架构，位于 `app/routes/settings/profile/` 目录下：

```
settings/profile/
├── _layout.tsx              # 布局组件（面包屑导航、Outlet）
├── index.tsx                # 主设置页面（包含所有安全入口）
├── password.tsx             # 修改密码页面
├── password_.create.tsx     # 创建密码页面
├── change-email.tsx         # 修改邮箱页面
├── change-email.server.tsx  # 邮箱变更验证处理器
├── passkeys.tsx             # 通行密钥管理页面
├── connections.tsx          # 第三方连接管理
├── photo.tsx                # 头像设置
└── two-factor/              # 双因素认证子路由
    ├── _layout.tsx
    ├── index.tsx            # 2FA 主页面
    ├── verify.tsx           # 2FA 验证页面
    └── disable.tsx          # 2FA 禁用页面
```

### 1.2 核心数据模型

基于 `prisma/schema.prisma`，安全相关的核心数据模型：

| 模型名 | 用途 | 关键字段 |
|--------|------|----------|
| `User` | 用户主表 | `email`, `username`, `name` |
| `Password` | 密码存储 | `hash` (bcrypt哈希) |
| `Session` | 会话管理 | `expirationDate`, `userId` |
| `Verification` | 验证令牌 | `type`, `target`, `secret`, `algorithm`, `expiresAt` |
| `Passkey` | 通行密钥 | `publicKey`, `counter`, `deviceType`, `backedUp` |
| `Connection` | 第三方连接 | `providerName`, `providerId` |

### 1.3 前后端交互模式

所有安全设置页面采用 **Remix Loader/Action** 模式：

- **Loader**: 服务端数据获取（检查当前状态、加载用户数据）
- **Action**: 服务端数据提交（处理表单、更新数据库）
- **前端状态**: 使用 `useFetcher` 或 `Form` + `useNavigation` 管理提交状态
- **表单验证**: `@conform-to/react` + `zod` 实现前后端统一验证

```typescript
export async function shouldRequestTwoFA(request: Request) {
  // 1. 检查是否有待验证的会话
  if (verifySession.has(unverifiedSessionIdKey)) return true
  
  // 2. 检查用户是否启用了 2FA
  const userHasTwoFA = await prisma.verification.findUnique({
    where: { target_type: { target: userId, type: twoFAVerificationType } },
  })
  if (!userHasTwoFA) return false
  
  // 3. 检查最近验证时间（超过2小时需要重新验证）
  const verifiedTime = authSession.get(verifiedTimeKey) ?? new Date(0)
  const twoHours = 1000 * 60 * 2
  return Date.now() - verifiedTime > twoHours
}

// Loader: 确保用户没有密码
async function requireNoPassword(userId: string) {
  const password = await prisma.password.findUnique({
    select: { userId: true },
    where: { userId },
  })
  if (password) {
    throw redirect('/settings/profile/password')  // 已有密码则跳转
  }
}

// Action: 创建密码
export async function action({ request }: Route.ActionArgs) {
  const userId = await requireUserId(request)
  await requireNoPassword(userId)
  
  const submission = await parseWithZod(formData, {
    schema: CreatePasswordForm.superRefine(async ({ password }, ctx) => {
      // 1. 弱密码检测（调用 pwnedpasswords API）
      const isCommonPassword = await checkIsCommonPassword(password)
      if (isCommonPassword) {
        ctx.addIssue({ path: ['password'], code: 'custom', message: 'Password is too common' })
      }
    }),
  })
  
  if (submission.status === 'success') {
    // 2. 生成 bcrypt 哈希
    const hashedPassword = await getPasswordHash(password)
    
    // 3. 创建 Password 记录（关联到 User）
    await prisma.user.update({
      where: { id: userId },
      data: {
        password: {
          create: { hash: hashedPassword },  // 创建关联
        },
      },
    })
    
    return redirect(`/settings/profile`, { status: 302 })
  }
}
```

### 3.4 弱密码检测实现

`checkIsCommonPassword` 位于 `auth.server.ts:269`：

```typescript
export async function checkIsCommonPassword(password: string) {
  // 1. 计算 SHA-1 哈希（k-匿名性：只发送前5位）
  const [prefix, suffix] = getPasswordHashParts(password)
  // prefix = 前5位十六进制
  // suffix = 剩余35位
  
  // 2. 调用 HIBP (Have I Been Pwned) API
  const response = await fetch(
    `https://api.pwnedpasswords.com/range/${prefix}`,
    { signal: AbortSignal.timeout(1000) },
  )
  
  // 3. 本地比对后缀（保护用户隐私）
  const data = await response.text()
  return data.split(/\r?\n/).some((line) => {
    const [hashSuffix] = line.split(':')
    return hashSuffix === suffix
  })
}
```

      to: submission.value.email,
      subject: `Epic Notes Email Change Verification`,
      react: <EmailChangeEmail verifyUrl={verifyUrl.toString()} otp={otp} />,

    if (response.status === 'success') {

export async function handleVerification({ request, submission }: VerifyFunctionArgs) {
  await requireRecentVerification(request)  // 安全检查
  
  // 1. 从 verifySession 获取新邮箱（必须在同一设备上）
  const verifySession = await verifySessionStorage.getSession(
    request.headers.get('cookie'),
  )
  const newEmail = verifySession.get(newEmailAddressSessionKey)
  
  if (!newEmail) {
    return data({
      result: submission.reply({
        formErrors: [
          'You must submit the code on the same device that requested the email change.',
        ],
      }),
    }, { status: 400 })
  }
  
  // 2. 获取旧邮箱（用于发送通知）
  const preUpdateUser = await prisma.user.findFirstOrThrow({
    select: { email: true },
    where: { id: submission.value.target },
  })
  
  // 3. 更新用户邮箱
  const user = await prisma.user.update({
    where: { id: submission.value.target },
    select: { id: true, email: true, username: true },
    data: { email: newEmail },
  })
  
  // 4. 异步发送通知到旧邮箱（不阻塞主流程）
  void sendEmail({
    to: preUpdateUser.email,
    subject: 'Epic Stack email changed',
    react: <EmailChangeNoticeEmail userId={user.id} />,
  })
  
  // 5. 清理 verifySession 并重定向
  return redirectWithToast(
    '/settings/profile',
    {
      title: 'Email Changed',
      type: 'success',
      description: `Your email has been changed to ${user.email}`,
    },
    {
      headers: {
        'set-cookie': await verifySessionStorage.destroySession(verifySession),
      },
    },
  )
}

### 4.3 验证流程的统一调度

所有验证类型都通过 `verify.server.ts` 的 `validateRequest` 统一处理：

```typescript
export async function validateRequest(request: Request, body: URLSearchParams | FormData) {
  // 1. 验证 OTP 有效性
  const submission = await parseWithZod(body, {
    schema: VerifySchema.superRefine(async (data, ctx) => {
      const codeIsValid = await isCodeValid({
        code: data[codeQueryParam],
        type: data[typeQueryParam],
        target: data[targetQueryParam],
      })
      if (!codeIsValid) {
        ctx.addIssue({ path: ['code'], message: `Invalid code` })
      }
    }),
  })
  
  if (submission.status !== 'success') {
    return data({ result: submission.reply() }, { status: 400 })
  }
  
  // 2. 准备删除验证记录（一次性使用）
  async function deleteVerification() {
    await prisma.verification.delete({
      where: {
        target_type: {
          type: submissionValue[typeQueryParam],
          target: submissionValue[targetQueryParam],
        },
      },
    })
  }
  
  // 3. 根据验证类型分发到对应处理器
  switch (submissionValue[typeQueryParam]) {
    case 'reset-password': {
      await deleteVerification()
      return handleResetPasswordVerification({ request, body, submission })
    }
    case 'onboarding': {
      await deleteVerification()
      return handleOnboardingVerification({ request, body, submission })
    }
    case 'change-email': {
      await deleteVerification()
      return handleChangeEmailVerification({ request, body, submission })
    }
    case '2fa': {
      return handleLoginTwoFactorVerification({ request, body, submission })
    }
  }
}

export async function loader({ request }: Route.LoaderArgs) {
  const userId = await requireUserId(request)
  
  // 1. 获取用户已有 passkey（用于 excludeCredentials）
  const passkeys = await prisma.passkey.findMany({
    where: { userId },
    select: { id: true },
  })
  
  const user = await prisma.user.findUniqueOrThrow({
    where: { id: userId },
    select: { email: true, name: true, username: true },
  })
  
  // 2. 生成 WebAuthn 注册选项
  const config = getWebAuthnConfig(request)
  const options = await generateRegistrationOptions({
    rpName: config.rpName,
    rpID: config.rpID,
    userName: user.username,
    userID: new TextEncoder().encode(userId),
    userDisplayName: user.name ?? user.email,
    attestationType: 'none',
    excludeCredentials: passkeys,  // 排除已注册的密钥
    authenticatorSelection: {
      residentKey: 'preferred',
      userVerification: 'preferred',
    },
  })
  
  // 3. 将 challenge 存储到 HttpOnly Cookie（防止 CSRF）
  return Response.json(
    { options },
    {
      headers: {
        'Set-Cookie': await passkeyCookie.serialize(
          PasskeyCookieSchema.parse({
            challenge: options.challenge,
            userId: options.user.id,
          }),
        ),
      },
    },
  )
}

  const { verified, registrationInfo } = verification
  if (!verified || !registrationInfo) {
    throw new Error('Registration verification failed')
  }
  
  const { credential, credentialDeviceType, credentialBackedUp, aaguid } =
    registrationInfo
  
  // 4. 检查是否已注册
  const existingPasskey = await prisma.passkey.findUnique({
    where: { id: credential.id },
    select: { id: true },
  })
  
  // 5. 创建 Passkey 记录
  await prisma.passkey.create({
    data: {
      id: credential.id,
      aaguid,
      publicKey: Buffer.from(credential.publicKey),  // 二进制存储
      userId,
      webauthnUserId,
      counter: credential.counter,  // 签名计数器（防重放）
      deviceType: credentialDeviceType,  // 'platform' 或 'cross-platform'
      backedUp: credentialBackedUp,  // 是否同步到云端
      transports: credential.transports?.join(','),  // 传输方式
    },
  })
  
  // 6. 清理 challenge Cookie
  return Response.json({ status: 'success' } as const, {
    headers: {
      'Set-Cookie': await passkeyCookie.serialize('', { maxAge: 0 }),
    },
  })
}
```

### 6.2 统一验证流程

`prepareVerification` 函数 (`verify.server.ts:76`) 是所有 OTP 验证的统一入口：

```typescript
export async function prepareVerification({
  period,      // 有效期（秒）
  request,
  type,        // 验证类型: 'onboarding' | 'reset-password' | 'change-email' | '2fa'
  target,      // 目标（通常是 userId）
}: {
  period: number
  request: Request
  type: VerificationTypes
  target: string
}) {
  // 1. 构建验证页面 URL
  const verifyUrl = getRedirectToUrl({ request, type, target })
  const redirectTo = new URL(verifyUrl.toString())
  
  // 2. 生成 TOTP 配置
  const { otp, ...verificationConfig } = await generateTOTP({
    algorithm: 'SHA-256',
    charSet: 'ABCDEFGHJKLMNPQRSTUVWXYZ123456789',  // 易混淆字符排除
    period,
  })
  
  // 3. 存储到 Verification 表（upsert 支持重试）
  const verificationData = {
    type,
    target,
    ...verificationConfig,
    expiresAt: new Date(Date.now() + verificationConfig.period * 1000),
  }
  await prisma.verification.upsert({
    where: { target_type: { target, type } },
    create: verificationData,
    update: verificationData,
  })
  
  // 4. 将 OTP 添加到邮件链接（用户点击时自动填充）
  verifyUrl.searchParams.set(codeQueryParam, otp)
  
  return { otp, redirectTo, verifyUrl }
}
```

### 6.3 会话与验证的双重存储

系统使用**两种独立的 Session Storage** 实现安全隔离：

| 存储类型 | Cookie 名称 | 用途 | 特性 |
|---------|------------|------|------|
| `authSessionStorage` | `en_session` | 主会话（登录状态） | 存储 `sessionId`、`verifiedTime` |
| `verifySessionStorage` | `en_verification` | 临时验证数据 | 存储 `unverifiedSessionIdKey`、`newEmail` 等 |

**关键设计意图**：

1. **验证流程与主登录分离**：2FA 验证时，会话先创建为"未验证"状态，存储在 `verifySession` 中
2. **防止会话劫持**：`verifiedTime` 字段实现"最近验证"检查，敏感操作需要重新验证
3. **跨请求临时数据**：邮箱变更时，新邮箱地址存储在 `verifySession` 中，确保只能在原设备完成验证

### 6.4 登录时的 2FA 集成

`handleNewSession` (`login.server.ts:17`) 展示了模块间的紧密协作：

```typescript
export async function handleNewSession(
  { request, session, redirectTo, remember }: { ... },
  responseInit?: ResponseInit,
) {
  // 1. 检查用户是否启用 2FA
  const verification = await prisma.verification.findUnique({
    select: { id: true },
    where: {
      target_type: { target: session.userId, type: twoFAVerificationType },
    },
  })
  const userHasTwoFactor = Boolean(verification)
  
  if (userHasTwoFactor) {
    // 2. 用户有 2FA：创建"未验证"会话，重定向到验证页面
    const verifySession = await verifySessionStorage.getSession()
    verifySession.set(unverifiedSessionIdKey, session.id)
    verifySession.set(rememberKey, remember)
    
    const redirectUrl = getRedirectToUrl({
      request,
      type: twoFAVerificationType,
      target: session.userId,
      redirectTo,
    })
    
    return redirect(
      `${redirectUrl.pathname}?${redirectUrl.searchParams}`,
      combineResponseInits(
        {
          headers: {
            'set-cookie': await verifySessionStorage.commitSession(verifySession),
          },
        },
        responseInit,
      ),
    )
  } else {
    // 3. 用户无 2FA：直接创建完整会话
    const authSession = await authSessionStorage.getSession(
      request.headers.get('cookie'),
    )
    authSession.set(sessionKey, session.id)
    
    return redirect(
      safeRedirect(redirectTo),
      combineResponseInits(
        {
          headers: {
            'set-cookie': await authSessionStorage.commitSession(authSession, {
              expires: remember ? session.expirationDate : undefined,
            }),
          },
        },
        responseInit,
      ),
    )
  }
}
```

## 7. 关键设计模式总结

### 7.1 状态同步模式

| 模式 | 应用场景 | 实现位置 |
|------|---------|---------|
| **Loader 预检查** | 页面加载时验证状态 | 所有 `loader` 函数 |
| **Action 后重定向** | 表单提交后刷新状态 | 所有 `action` 返回 `redirect()` |
| **useRevalidator** | Passkey 列表刷新 | `passkeys.tsx` 注册后 |
| **useFetcher** | 无刷新提交（如登出其他会话） | `index.tsx` 中的 `SignOutOfSessions` |

### 7.2 安全防护模式

| 防护类型 | 实现机制 | 代码位置 |
|---------|---------|---------|
| **CSRF 防护** | `sameSite: 'lax'` Cookie + challenge 验证 | `session.server.ts`, `webauthn/utils.server.ts` |
| **重放攻击防护** | TOTP 一次性使用 + 签名计数器 | `verify.server.ts`, `Passkey.counter` |
| **弱密码防护** | pwnedpasswords API 检查 + bcrypt 哈希 | `auth.server.ts:checkIsCommonPassword` |
| **验证超时** | `expiresAt` 字段 + 2 小时重验证 | `Verification.expiresAt`, `shouldRequestTwoFA` |
| **所有权验证** | 操作时验证 `userId` 匹配 | `Passkey.delete({ where: { id, userId } })` |

### 7.3 数据一致性保证

1. **数据库事务**：Prisma 的 `update` 操作是原子的
2. **一次性验证**：`Verification` 记录验证成功后立即删除
3. **双重写入防护**：邮箱变更时，旧邮箱通知采用 `void sendEmail()` 异步发送，不影响主流程
4. **会话失效**：修改密码/2FA 后，其他会话可通过 "Sign out of other sessions" 手动清除
